# web-search-agent

**Owner:** Person A (team-search) · **Port:** 8201 · **Graph id:** `web_search` · **UI:** `frontend/agents/web_search_ui` :4301

One step of the orchestrator's plan: **input from the supervisor** (and optionally the RAG agent), **output to the
verifier**.

```
supervisor ─{"task": AgentTask}─► web_search ─{"result": question + top 3 contents}─► verifier (other machine)
   (rag ─result─► task.inputs, when the plan says depends_on)

plan_queries ─► Send(search × N) ─► select_pages ─► Send(extract × M) ─► rank ─► finalize ─► send_output
 read task,      Tavily → SearXNG    merge +         httpx +             chunk +   question +   POST to every
 fast LLM plans  → DuckDuckGo        de-duplicate    Trafilatura         BM25 →    top 3        WEB_SEARCH_VERIFIER_PATH
 1-3 queries     + Wikipedia                         (4 pages,           MiniLM    contents     route on the network;
                 (parallel)                          trusted first)      cross-enc.            saves the run (Retry)
```

## Input (from the supervisor)

`task.objective` is searched; `task.params` (`card.WebSearchParams`, all optional):

| Param | Example | Effect |
|---|---|---|
| `query` | `"iPhone price"` | search this instead of the objective |
| `region` | `"Oman"` | appended: "iPhone price in Oman" |
| `freshness` | `"week"` | only recent sources (default: the planner decides) |
| `include_domains` / `exclude_domains` | `["reuters.com"]` | domain filters |

**From the RAG agent** (or any step this one `depends_on`): the orchestrator puts that step's `result` in
`task.inputs[<step id>]`. The agent reads, from each upstream result:

| Key | Used for |
|---|---|
| `search_query` (str) / `search_queries` (list) | searched as well (after the planner's queries) |
| `answer` or `summary` | given to the query planner as "already found", so it searches for what is missing |

Without an LLM, the question and the upstream queries are searched as they are.

## Output (to the verifier)

Only the question and the top 3 contents (`WEB_SEARCH_RESULT_TOP_N`), plus the platform's required fields:

```json
{"result": {
  "status": "ok",
  "summary": "Question: iPhone price in Oman\n\nTop 3 web results:\n\n[1] Title - https://…\npassage…",
  "question": "iPhone price in Oman",
  "findings": [{"rank": 1, "title": "…", "url": "https://…", "content": "passage…"}, "… 3 items"],
  "sources": ["https://…", "https://…", "https://…"]
}}
```

- `status: failed` (no results) makes the supervisor replan. `summary` is what the chat answer and emails show.
- `findings` / `sources` are the names the verifier checks (non-empty, valid URLs).
- The agent does not write an answer (no summarizer): the verifier, and later steps, work from the top contents.
  The agent page's console shows the full run: all ranked evidence, sources, flow and timings (streamed; also in
  `/custom/history`, `/custom/sources`).

## Where the output goes (`backend/.env`)

```
WEB_SEARCH_VERIFIER_PATH=/verify,/synthesize   # POST routes; empty = send nothing
WEB_SEARCH_VERIFIER_PORT=8203                  # or several: 8203,8230
```

The last node, `send_output`, finds **every machine of the network that has one of these POST routes** on the port
and sends the output to each of them in parallel - e.g. `http://192.168.1.25:8203/verify` and
`http://192.168.1.33:8203/synthesize`. No IPs or URLs to configure (`services/handoff.py`):

- one network scan (the /24 of this machine's IP; `WEB_SEARCH_DISCOVERY_SUBNETS` for others), 2 s connect timeout,
  2 tries per machine - a flapping Wi-Fi link is still found; this machine counts once;
- each machine's routes come from its OpenAPI spec (`GET /openapi.json`, generated by FastAPI and by `langgraph dev`,
  custom routes included), or, without a spec, a GET on each route (405 = the POST route exists);
- found routes are reused for 10 minutes; a POST is retried 3 times on connection errors, and after a failure or a
  404/405 the network is searched again once;
- one body for every route: `{"task": {...}, "question": "...", "inputs": {"web_search": <output>}}` - the verifier
  reads `task` (what the orchestrator would send: `task.inputs` holds the output), the synthesizer `question`/`inputs`.

Each response is kept in the run details (`handoffs`: one entry per URL; a verifier's verdict is shown as passed /
failed). A route that is not found or not reachable is only a warning in the "Send output" step - the search result
is unchanged. Health: `http://127.0.0.1:8201/custom/health` → `output.urls`.

**On the other machines** (not this agent's code): the route must exist and the server must listen on the network,
e.g. the verifier in `verifier-agent/src/verifier_agent/api.py`:

```python
from verifier_agent.graph import graph

@app.post("/verify")
async def verify(body: dict) -> dict:
    out = await graph.ainvoke({"task": body["task"]})
    return {"result": out["result"]}
```

started with `--host 0.0.0.0 --port 8203` (`langgraph dev` or `uvicorn`), inbound TCP 8203 allowed in the firewall
(Windows, admin: `New-NetFirewallRule -DisplayName "agent 8203" -Direction Inbound -Protocol TCP -LocalPort 8203
-Action Allow`). Check from this machine: `curl http://<ip>:8203/openapi.json`.

When this agent runs inside an orchestrator plan, the orchestrator adds its own verifier step: leave
`WEB_SEARCH_VERIFIER_PATH` empty there to avoid verifying twice.

## Sources

- **Search**: `WEB_SEARCH_PROVIDERS=google,tavily,duckduckgo` - the first one that answers is used. Google needs a free
  Programmable Search key + engine id (`WEB_SEARCH_GOOGLE_API_KEY`, `WEB_SEARCH_GOOGLE_CSE_ID`, 100 searches/day);
  without them it is skipped and Tavily is used.
- **Wikipedia on every search**: its own search API (free, no key); the 2 best articles per query are merged in first
  (`WEB_SEARCH_ALWAYS_PROVIDERS=wikipedia`, empty = off).
- **Blocked**: social media, video and forums are never used - facebook, instagram, tiktok, x/twitter, youtube,
  pinterest, linkedin, reddit, quora, threads, snapchat (`WEB_SEARCH_BLOCKED_DOMAINS`).
- **Trusted first**: Wikipedia, Britannica, Reuters, AP, BBC, WHO, UN and any government (`gov`) or university
  (`edu`) site are read first and get a ranking boost (`WEB_SEARCH_TRUSTED_DOMAINS`, `WEB_SEARCH_TRUSTED_BOOST=0.15`).
- **Fewer sources**: 5 results per query, 8 in total, 4 pages read; the top 3 contents come from 3 different pages
  where possible.

## Reranker

`cross-encoder/ms-marco-MiniLM-L-6-v2` (90 MB). Measured on a real run: 2.9 s for 40 passages vs 12.2 s with
`BAAI/bge-reranker-base` (1.1 GB), same top results. It is downloaded **once** into
`backend/web_search_agent/models/` (git-ignored; `WEB_SEARCH_RERANKER_DIR`) and always loaded from there - no
Hugging Face checks on every start, works offline. Another model: set `WEB_SEARCH_RERANKER_MODEL`
(e.g. `BAAI/bge-reranker-v2-m3`, multilingual, best with a GPU); it is downloaded once the same way.

## Retry

Every run is saved when its output is sent (`backend/web_search_agent/logs/checkpoints/<trace_id>.json`, git-ignored;
newest 200 kept) - before sending, so a crash can be retried too. **Retry** - the button on the *Send output* step,
on the result and in *Recent runs*, or `POST /custom/retry?trace_id=<id>` - sends another request to the output
agents with that run: it rebuilds the top N contents (a changed `WEB_SEARCH_RESULT_TOP_N` applies) and sends them.
No search, no page fetching, no reranking, no LLM call; works after a restart too.

## Configuration (`backend/.env`, section `web_search_agent`)

All agents share one `.env` (git-ignored; template: `backend/.env.example`):

```powershell
cd backend
copy .env.example .env
```

Priority: real environment variables > `backend/web_search_agent/.env` (optional override, not needed) > `backend/.env`.
Tests never use your live keys or call the verifier machine: `backend/conftest.py` removes every `WEB_SEARCH_*`
variable for each test. With Docker, compose passes `backend/.env` in (`env_file`); it is never copied into the image.

Every key starts with `WEB_SEARCH_` (see `settings.py`). Main ones:

| Key | Default | |
|---|---|---|
| `WEB_SEARCH_PROVIDERS` | `sample` | offline placeholder data; live: `google,tavily,duckduckgo` |
| `WEB_SEARCH_GOOGLE_API_KEY` / `_CSE_ID` | – | Google Programmable Search (optional) |
| `WEB_SEARCH_ALWAYS_PROVIDERS` | `wikipedia` | also searched on every query |
| `WEB_SEARCH_TAVILY_API_KEY` | – | https://app.tavily.com |
| `WEB_SEARCH_OPENAI_API_KEY` | – | query planning (the only LLM call); empty = question searched as-is |
| `WEB_SEARCH_OPENAI_FAST_MODEL` | `gpt-4o-mini` | |
| `WEB_SEARCH_RESULT_TOP_N` | `3` | contents in the step result |
| `WEB_SEARCH_VERIFIER_PATH` | – | POST routes to send the output to, e.g. `/verify,/synthesize` |
| `WEB_SEARCH_VERIFIER_PORT` | `8203` | port(s) they are looked for on, e.g. `8203,8230` |
| `WEB_SEARCH_RERANKER_MODEL` | `cross-encoder/ms-marco-MiniLM-L-6-v2` | downloaded once to `models/`; BM25 fallback |

`sample` never downloads pages or the reranker, so CI and the orchestrator's tests run offline.

## Run (backend + its UI, one terminal)

```powershell
cd backend\web_search_agent
python run.py --install     # first time: pip install -r requirements.txt + npm install (in frontend/)
python run.py               # agent :8201 + web-search-ui :4301; Ctrl+C stops both
```

`--backend-only` / `--frontend-only`, `--no-reload`, `--host 0.0.0.0` (reachable from other machines).
Use the Python environment (3.11 - 3.13) you installed `requirements.txt` into. Ports 8201 / 4301 are checked
first; the backend restarts when `src/`, `backend/utils`, the `.env` files or `langgraph.json` change.
UI: http://localhost:4301.

The log is one readable stream (`runlog.py`): local time, `run` / `backend` / `frontend`, message. Every search is
a `▶` line, one line per finished step and a `■` summary (`↻` for Retry):

```text
11:38:10  backend   ▶ Search "who won the 2026 FIFA world cup"  (from web-search-ui, trace cb80aedf)
11:38:11  backend     ✓ Query planner    1 query by gpt-4o-mini (1.2 s): 2026 FIFA World Cup winner
11:38:13  backend     ✓ Web search       7 results via tavily,wikipedia (1.9 s)
11:38:18  backend     ✓ Fetch & extract  4/4 pages extracted with Trafilatura (5.4 s)
11:38:21  backend     ✓ Rerank           40 -> 5 passages (cross-encoder/ms-marco-MiniLM-L-6-v2) (2.6 s)
11:38:21  backend     ✓ Send output      /verify @ 192.168.1.30: Verification passed (0.1 s)
11:38:21  backend   ■ Done in 11.2 s: 3 contents, /verify passed  (trace cb80aedf)
```

Server internals, the startup banner, npm / vite / build-table noise and single HTTP requests are left out;
warnings (yellow) and errors (red) are always shown. `--verbose` adds every HTTP request, `--layout split` shows
`FRONTEND │ BACKEND` columns, `--raw` the original lines. The same log, without colours, is written to
`logs/run.log` (new on every start). The step lines come from the agent itself (`steps.log_step`), so
`docker compose logs` and orchestrator runs show them too.

Backend alone, without run.py: `langgraph dev --port 8201 --no-browser` (from this folder).

### Docker

```powershell
cd backend\web_search_agent
docker compose up --build        # this agent only, :8201 (docker-compose.yml here)
```

Or as part of the platform: `docker compose up --build web-search-agent` (from `backend/`). The image
(`Dockerfile`, build context `backend/`) has only this agent's dependencies with CPU-only torch; build args
`TORCH_INDEX_URL` (e.g. a CUDA wheel index) and `PLAYWRIGHT=true` (Chromium for JS pages). `models/` (the reranker)
and `logs/` (saved runs for Retry) are mounted from this folder, so the model is downloaded once and Retry works after
a restart. Inside the container "this machine's network" is Docker's network: set `WEB_SEARCH_DISCOVERY_SUBNETS`
(e.g. `192.168.1.0/24`) so the output reaches the verifier / synthesizer machines on your LAN.

- Card (orchestrator discovery): http://127.0.0.1:8201/card · health: http://127.0.0.1:8201/custom/health
- Studio: https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:8201

Routes for the UI (`api.py`, via `/api/agents/web-search/*`): `POST /custom/search/stream` (SSE: `steps`, `step`…,
`result`), `GET /custom/history`, `GET /custom/sources[?trace_id=]`, `GET /custom/health`.
